# Personal Team local iPhone build

## Purpose and boundary

Apple Personal Teams cannot provision the Push Notifications capability. MedicineApp therefore has one explicit, non-secret local build switch:

`MEDICINEAPP_IOS_PERSONAL_TEAM_BUILD=true`

The switch adds a source-controlled Expo config plugin after `expo-notifications` that removes the generated `aps-environment` entitlement only for that explicitly selected configuration. Consequently, a clean iOS prebuild contains no Push Notifications entitlement. The same harmless boolean is exposed in Expo `extra` so the runtime returns `unsupported_personal_team` before loading the native notification module, requesting permission, acquiring a token, or calling the backend registration API. Notification settings explain that other features remain usable.

This switch must not be set for EAS development, preview, staging, or production builds. With it absent or `false`, the entitlement-removal plugin is absent and the standard notification plugin, APNs entitlement readiness, Android notification channel, and backend-mediated push flow remain unchanged.

## Regenerate and open the local project

From the repository root run:

```sh
MEDICINEAPP_IOS_PERSONAL_TEAM_BUILD=true npx expo prebuild --platform ios --clean
open ios/MedicineApp.xcworkspace
```

In Xcode:

1. Select the MedicineApp project and application target.
2. Under Signing & Capabilities, select “Upendra Dharmagadi (Personal Team)” and enable automatic signing.
3. Confirm bundle identifier `com.medicineapp.mobile` and confirm Push Notifications is absent.
4. Select the connected iPhone 16, ensure Developer Mode/trust requirements are satisfied, then Build and Run.
5. Start Metro with the same bounded configuration so the development manifest preserves the runtime capability: `MEDICINEAPP_IOS_PERSONAL_TEAM_BUILD=true npx expo start --dev-client`.
6. Use the installed app for the bounded physical-device smoke plan.

The `package.json` `ios`/`android` scripts generated by prebuild are retained because `expo run:ios` and `expo run:android` are Expo's native compile/install commands. `npx expo start` remains the normal server command after installation.

## Evidence limitation

This mode is not APNs validation evidence. Push is deliberately unavailable and no fake registration is reported. Full push testing requires a normally configured installed EAS/native build signed by an Apple Developer team that supports Push Notifications.
